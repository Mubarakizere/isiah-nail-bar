# Isaiah Nail Bar

The application is a two-part monorepo:

- `frontend/` is the Next.js website and admin interface.
- `backend/` is the Laravel API, database layer, payment/webhook handlers, queued mail, PDFs, sitemap, and uploaded files.

Laravel no longer serves page templates. The remaining Blade templates were removed after replacing custom mail, PDF, and sitemap rendering with HTML/XML generated by backend classes.

## Local development

Configure the Laravel environment in `backend/.env`. Point `APP_URL` to the Laravel server and `FRONTEND_URL` to the Next.js origin. Set the database and payment/mail credentials for the environment you intend to use.

Terminal 1:

```powershell
cd backend
composer install
php artisan storage:link
php artisan serve --host=127.0.0.1 --port=8000
```

Terminal 2:

```powershell
cd frontend
npm ci
npm run dev
```

Terminal 3 (process queued mail, SMS, and other Laravel jobs):

```powershell
cd backend
php artisan queue:work database --queue=default --sleep=3 --tries=3 --timeout=90
```

Terminal 4 (run scheduled reminders and booking cleanup):

```powershell
cd backend
php artisan schedule:work
```

The website is served at `http://localhost:3000`; Next.js proxies `/api/*`, `/storage/*`, and `/sitemap.xml` to Laravel at `http://127.0.0.1:8000` by default. Set `LARAVEL_API_URL` in `frontend/.env.local` when the Laravel API uses another origin.

## Quality checks

GitHub Actions runs Laravel syntax checks and feature tests, then runs the Next.js linter, TypeScript check, and production build on every push and pull request. Run the same checks locally with:

```powershell
cd backend
php artisan test

cd ..\frontend
npm run lint
npm run typecheck
npm run build
```

## Docker

The Compose stack runs Laravel, Next.js, and MySQL. Set the local Docker database credentials and Laravel key in `backend/.env`, then run:

```powershell
docker compose --env-file backend/.env up --build
```

Next.js is exposed at `http://localhost:3000`; Laravel is available at `http://localhost:8000` for API and health checks.
Compose also starts dedicated Laravel queue and scheduler containers. The scheduler evaluates reminder work every minute; the queue container retries failed work and restarts automatically.

## Deployment

Deploy Laravel from `backend/` with the web root set to `backend/public`, and run Next.js in a Node.js hosting environment. Configure `LARAVEL_API_URL` on the Next.js server to point to the Laravel origin, and configure `FRONTEND_URL` in Laravel to point back to the public Next.js site. cPanel tasks operate from `$DEPLOYPATH/backend`; they do not build or run the Next.js process.

For cPanel or another host without Docker, set `QUEUE_CONNECTION=database` and `DB_QUEUE_RETRY_AFTER=120` in `backend/.env`, then add these cron entries. Replace the paths with the deployed application paths and confirm the `flock` binary path with `command -v flock` on the host:

```cron
* * * * * cd /home/stockcen/repository/backend && /usr/local/bin/php artisan schedule:run >> storage/logs/scheduler.log 2>&1
* * * * * cd /home/stockcen/repository/backend && /usr/bin/flock -n /tmp/isaiah-nailbar-queue.lock /usr/local/bin/php artisan queue:work database --stop-when-empty --sleep=1 --tries=3 --timeout=90 >> storage/logs/queue-worker.log 2>&1
```

The scheduler must run once per minute. The queue cron starts a worker that drains available jobs and exits, while `flock` prevents overlapping workers. After deployment, run `php artisan migrate --force`; use `php artisan queue:failed` to inspect exhausted jobs and `php artisan queue:retry all` after fixing their cause.

Uploaded files remain under `backend/storage/app/public`, exposed through `backend/public/storage`. Keep the Laravel database and storage volume persistent when deploying or rebuilding containers.
